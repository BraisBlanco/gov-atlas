# Parallel work: who owns which files

This project is built by several agents at once. The only thing that makes that safe is
**exclusive file ownership**: every file has one owner per phase, and no two tracks write to
the same path. Merge conflicts in a dataset are not a nuisance, they are silent data loss.

## The rule that makes it work

1. **Create files, do not edit shared ones.** A curator adds two new files. A chart author
   adds one new component. Nobody edits a file another track owns.
2. **No barrel files.** There is no `index.ts` re-exporting components, and there will not
   be. A barrel is a file every track must edit, which is exactly the thing we are avoiding.
   Import components by their own path.
3. **No shared registries.** Charts are wired into pages by the assembly phase, by one
   agent, at the end. Do not add yourself to a central list.
4. **Taxonomies are frozen during fan-out.** Need a new policy area or exclusion reason?
   Put it in your hand-off notes. Adding an id changes every country's comparison row, so it
   is an assembly-phase decision.
5. **`npm run validate` clean before you hand off.** Always. It is the gate for everyone.

## Ownership table

| Path | Owner | Phase |
| --- | --- | --- |
| `data/schema/**`, `data/taxonomy/**` | foundations | M0, then frozen |
| `scripts/**` | foundations | M0, then frozen |
| `data/countries/<ISO2>.yml`, `data/cabinets/<ISO2>-*.yml` | the curator of that country | M1 track A |
| `site/src/components/charts/<OneChart>.tsx` | the author of that chart | M1 track B |
| `site/src/components/chart-frame/**`, `site/src/styles/**` | foundations | M0, then frozen |
| `site/src/pages/**`, `site/src/layouts/**`, `site/src/content/**`, `site/src/i18n/**` | site track | M1 track C |
| `site/public/data/**` | nobody — generated by `npm run build:data` | never edit by hand |
| `site/src/geo/**` | nobody — generated by `npm run build:geo` | never edit by hand; regenerating mid-fan-out changes every map |
| `docs/COVERAGE.md` | nobody — generated by `npm run report:coverage` | never edit by hand |

## What M0 has already delivered

Everything below exists and is stable. Build on it; do not re-derive it.

- **Schemas** — `data/schema/*.schema.ts` (Zod). The shape of every data file.
- **Taxonomies** — `data/taxonomy/*.yml`. Policy areas, exclusion reasons, source tiers.
- **The gate** — `scripts/validate.ts` and `scripts/lib/rules.ts`, with negative tests in
  `scripts/__tests__/rules.test.ts`.
- **Derivations** — `scripts/lib/derive.ts`. All published counts come from here.
- **The build** — `scripts/build-data.ts` writes `site/public/data/*.{json,csv}`.
- **Coverage** — `scripts/report-coverage.ts` writes `docs/COVERAGE.md`.
- **Spain** — fully curated, grade A, the template for the other 26.
- **Design tokens and `ChartFrame`** — the shared chart shell.
- **One end-to-end chart** — `RankedBars`, proving the whole circuit against real data.

## M1 — the fan-out

Tracks A, B and C run concurrently and do not block each other. B and C do not wait for A:
Spain is real data, and `site/src/fixtures/` holds synthetic countries for layout work.

### Track A — data curation (5 agents)

One agent per batch, from `scripts/lib/scope.ts`:

| Batch | Countries |
| --- | --- |
| A1 | DE AT NL BE LU |
| A2 | SE DK FI EE LV LT |
| A3 | PT IT GR MT CY |
| A4 | PL CZ SK HU SI |
| A5 | RO BG HR IE FR |

Brief for each: follow [DATA-CONTRACT.md](DATA-CONTRACT.md). Start from the official gazette
or government portal, never from an encyclopedia. Spain is your worked example. Write only
your own country files. Where the definition of a ministry is ambiguous in your country, **do
not decide silently** — record the entity with `counts_as_ministry: false` and a reason, add a
bilingual `methodology_notes` entry, and flag it in your hand-off notes.

Batches are grouped by administrative-vocabulary affinity so one curator reuses the same
terminology across their whole batch.

### Track B — charts (3 agents)

One component per file under `site/src/components/charts/`. Every chart wraps
`ChartFrame` and reads from `site/public/data/`. Load the `dataviz` skill before writing
chart code.

| Agent | Charts |
| --- | --- |
| B1 | `ChoroplethEurope` + the Eurostat GISCO geometry pipeline |
| B2 | `PolicyAreaHeatmap` + `CountryComparison` |
| B3 | `MinistryExplorer` (faceted table) + `CabinetTimeline` |

Each chart must: render from the published JSON, show the real citations behind the data it
draws, offer a CSV download of exactly what it drew, and work in light and dark themes.

### Track C — site and editorial (1 agent)

Layouts, home page, country page, navigation, i18n plumbing, and the MDX pages for
methodology and data quality in both languages. Owns `pages/`, `layouts/`, `content/`,
`i18n/` — disjoint from track B.

## M2 — assembly (1 agent, alone)

Wire the charts into the real pages, cross-review all 27 countries (derived count against
the cited source, spot-check `archive_url`s), Playwright smoke tests, publish coverage.
This is also where deferred taxonomy additions from track A are decided.

## Hand-off notes

Every agent finishes with a short report — not a summary of what the diff shows, but what
the diff cannot show:

1. **Judgement calls.** Anything where a defensible curator could have chosen otherwise.
2. **Exclusions.** Every entity you did not count, and why.
3. **Source weaknesses.** Anything that had to rest on tier 2 or 3, and what tier-1 source
   you looked for and could not find.
4. **Blocked wishes.** Taxonomy ids you wanted, fields the schema lacks.
5. **Contradictions.** Where two official sources disagreed, and which you followed.
