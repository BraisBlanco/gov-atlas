# Gov Atlas

How many ministries each country has, what they are called, and a citation for every figure.

A data site in the spirit of Our World in Data. Coverage starts with the EU-27 and the schema
carries no assumption that it stops there; ministries and cabinets are the first dataset, not
the whole of the intended atlas. Bilingual (Spanish and English) from the first commit —
neither language is the default, in the URLs or anywhere else.

**Status: 26 of the 27 target countries curated.** Cyprus is not started. Every other country
grades A except France and Ireland, which grade B. `docs/COVERAGE.md` is generated from the
data and CI fails if it drifts.

**`npm run validate` currently fails**, deliberately and visibly: the two Government Notices
that Malta's file rests on have no archive snapshot, because Save Page Now refused every
capture while that file was curated. The file records what was tried and what the next curator
must do. Nothing is invented to make the gate pass — that is the point of the gate.

## The one idea

"How many ministries does this country have?" has no factual answer — Germany has 15 federal
ministries or 16 depending on the Chancellery, Spain has 22 departments and 23 cabinet
members. The published number is therefore the consequence of a definition, so this project
makes the definition explicit and enforceable:

- **Counts are derived, never typed.** One row per ministry is curated; the figure is a
  `COUNT` computed at build time. A headline number cannot drift from the list beneath it.
- **Sources are a CI gate, not a convention.** An unsourced ministry, a citation that does not
  resolve, an unarchived legal instrument or an unexplained exclusion fails the build.
- **Exclusions are recorded.** Bodies that do not count are kept with a reason, so the number
  can be argued with instead of merely believed.

Read [docs/METHODOLOGY.md](docs/METHODOLOGY.md) before touching the data.

## Quick start

```bash
npm install
npm run validate        # the gate: schema, citations, archives, exclusions
npm test                # derivations + the negative tests that prove the gate works
npm run build:data      # data/ -> site/public/data/*.{json,csv}
npm run dev             # build data, then serve the site
npm run build           # validate -> build data -> build site
npm run report:coverage # regenerate docs/COVERAGE.md
npm run build:geo       # refetch the map geometry (rarely; the output is committed)
```

`site/public/data/` is generated and git-ignored, and the site imports it directly — so
`npm run build:data` must run before building or typechecking the site. The root `npm run
build` chains them in the right order.

`npm run build:geo` is deliberately *not* part of `npm run build`. It fetches country
boundaries from Eurostat GISCO, projects and clips them, and commits finished SVG paths to
`site/src/geo/europe-paths.json` — so the site builds offline and the same commit always
draws the same coastlines. Run it only to move to a newer GISCO release.

## Layout

```
data/                 SOURCE OF TRUTH — hand-curated YAML, one file per country and cabinet
  schema/             Zod schemas: the shape of every data file
  taxonomy/           controlled vocabularies (policy areas, exclusion reasons, source tiers)
  countries/          country metadata + a sourced population figure
  cabinets/           one cabinet per file, self-contained: entities *and* their sources
scripts/              validate · build:data · report:coverage · build:geo, plus their tests
site/                 Astro + React islands + design tokens
  src/geo/            committed map geometry (generated by build:geo, never hand-edited)
docs/                 METHODOLOGY · DATA-CONTRACT · AGENT-WORKFLOW · COVERAGE
```

## Contributing a country

Read [docs/DATA-CONTRACT.md](docs/DATA-CONTRACT.md). You create exactly two files —
`data/countries/<ISO2>.yml` and `data/cabinets/<ISO2>-<date>.yml` — and touch nothing else.
Spain is the worked example. `npm run validate` must be clean before you open a PR.

Several people (or agents) work in parallel on this; the file-ownership rules that keep that
safe are in [docs/AGENT-WORKFLOW.md](docs/AGENT-WORKFLOW.md).
